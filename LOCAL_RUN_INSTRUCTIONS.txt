FLOWTIX — ИНСТРУКЦИЯ ПО ЛОКАЛЬНОМУ ЗАПУСКУ

КАК ЗАПУСТИТЬ ДЛЯ ПОКАЗА

Веб-интерфейс FlowTix находится в ветке main. Серверная часть находится отдельно, в ветке server. База данных и API размещены в Supabase и Render.

Важно: нельзя полноценно запустить сайт простым двойным щелчком по index.html. Браузер ограничивает запросы к API и авторизацию со страниц file://. Для запуска интерфейса используйте VS Code и расширение Live Server. Команды npm и npm-скрипты для этого способа не нужны.

1. Скачайте или клонируйте ветку main репозитория cursovuxa/curs и откройте её папку в Visual Studio Code.
2. Установите расширение Live Server, если оно ещё не установлено.
3. Откройте index.html и нажмите Go Live в нижней панели VS Code. Сайт откроется по адресу вроде http://127.0.0.1:5500.
4. Для работы нужны интернет, доступный API на Render и доступная база Supabase. В index.js адрес API уже указан.

НАСТРОЙКА ДОСТУПА ДЛЯ ЛОКАЛЬНОГО АДРЕСА

Если сайт показывает ошибку CORS или не загружает данные:

1. В Render откройте настройки сервиса API и переменную FRONTEND_ORIGIN. Добавьте адрес Live Server, например http://127.0.0.1:5500. Если переменная уже содержит адрес сайта, сохраните его и добавьте локальный адрес через запятую.
2. В настройках Supabase Auth добавьте в Redirect URLs адрес возврата локального сайта, например http://127.0.0.1:5500/**. Для Google OAuth адрес callback провайдера остаётся адресом Supabase из раздела Auth Providers.
3. После сохранения настроек дождитесь перезапуска API, затем обновите локальный сайт.

Если Live Server использует другой порт или адрес localhost, укажите именно этот адрес в FRONTEND_ORIGIN и Redirect URLs.

ПОЛНЫЙ ЛОКАЛЬНЫЙ СЕРВЕР

Для запуска не только интерфейса, но и API на компьютере нужна отдельная копия ветки server, Node.js версии 20 или новее, зависимости сервера и переменные окружения Supabase. В частности, серверу нужны SUPABASE_URL и SUPABASE_SERVICE_ROLE_KEY; для входа через Supabase также используется SUPABASE_PUBLISHABLE_KEY. Адрес API в локальной копии index.js при этом меняют на http://localhost:10000. Секреты берут из защищённых настроек Render/Supabase и задают только на компьютере запускающего. Не помещайте их в HTML, JavaScript, этот файл или GitHub.

ОСНОВНЫЕ ФАЙЛЫ ДЛЯ КУРСОВОЙ

Клиентская часть, ветка main:
- index.html — главная страница и точка входа сайта;
- style.css — оформление и адаптация для телефона;
- index.js — логика интерфейса и запросы к API;
- 404.html — обработка прямых ссылок на страницы при публикации на GitHub Pages;
- profile/, dashboard/, admin/, messages/, notifications/ — отдельные страницы и разделы;
- logo.png, name.png, hallowen_name.png, favicon.svg — графические материалы бренда;
- vendor/ — используемые клиентские библиотеки и локальные ресурсы.

Серверная часть, ветка server:
- server.js — HTTP API и серверная бизнес-логика;
- package.json — зависимости и версия Node.js для API;
- supabase/migrations/ — миграции схемы базы данных;
- migrations/ — дополнительные SQL-файлы сервера;
- PAYMENT_PROVIDER.md — описание подготовки интеграции платежей, если требуется раскрыть её в отчёте.

Для передачи преподавателю сохраняйте ветки main и server раздельно. Не прикладывайте node_modules, папку .git, .env, секретный ключ Supabase service role, токен Telegram-бота, ключи платежей и другие секреты. Публичный интерфейс сайта обращается к API, а сервер — к Supabase; одного HTML-файла для всех функций недостаточно.
